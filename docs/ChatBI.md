# ChatBI：对话式智能看板（运营数据问答）

> 本文档记录 2026-08 与产品方的需求讨论与架构决策，作为实现依据。
> 状态：**已确认，待实现**

## 1. 功能定位

运营人员用自然语言描述数据需求，系统取数 → 生成图表看板 / 报告，支持下载。

行业定位：**ChatBI（对话式 BI）**——自然语言问数 + 数据可视化 + 看板 + 导出 + 报告。
参考：观远 ChatBI、帆软 ChatBI、腾讯云 ChatBI、阿里云小Q报告、网易数帆 AI 报告。

## 2. 需求结论（产品方确认）

| # | 需求 | 行业对应 | 结论 |
|---|---|---|---|
| 1 | 前端看板，动态、可调节 | Dashboard | **核心形态**。一期：自动排布多图表看板；"可调节"（拖拽/筛选联动）待真实需求再加 |
| 2 | PNG 图 = 看板截图 | 图表导出（分享） | 用于传播（群/PPT），不是日常检查形态 |
| 3 | Excel/CSV 下载，运营二次处理 | 数据导出 | 每图附带 CSV 导出（筛序是真实运营工作流） |
| 4 | 总结文字 + 图片 = 临时汇报/想法验证 | AI 报告 | 独立模式：summary 文字 + 相关图表 |
| 5 | 多图看板（"给我运营看板"） | 看板 | 一期预留：charts 数组，一条链路两种能力 |

## 3. 分工原则：AI 只做语义，其余交给确定性代码

| 环节 | 承担者 | 说明 |
|---|---|---|
| ① 语义解析（描述→数据集/分组/指标/图表类型） | **AI 网关（LLM）** | 唯一非 AI 不可的环节 |
| ② 报告总结文字 | **AI 网关（LLM）** | 仅报告模式 |
| ③ 取数 + 聚合 | **业务服务器（SQL）** | `/api/stats` 统计端点，SQL 聚合 |
| ④ TopN/排序/格式化后处理 | **AI 网关（确定性代码）** | 轻量，不占 LLM |
| ⑤ 图表渲染/option 模板 | **前端 mall-web** | **AI 不生成 option**（UI 是确定性细节，LLM 输出会漂移） |
| ⑥ 看板布局/交互/缩放/筛选 | **前端** | 纯前端 |
| ⑦ PNG 下载 | **前端** | ECharts `getDataURL` |
| ⑧ CSV 导出 | **前端** | 本地数据转 CSV |

**反模式警示**：让 LLM 直接输出 ECharts option JSON——颜色/坐标轴/格式漂移且浪费 token。模板写在前端，LLM 永远不碰。

## 4. 数据流与吞吐：数据不经过网关

```
运营一句话
  → AI 网关：LLM 解析 → {dataset, group_by, metric, chart_type, 是否总结}
  → AI 网关：确定性代码调 biz /api/stats（SQL 聚合）→ 拿聚合后的小数据
  → AI 网关：后处理（TopN/排序）→ charts: [{title, type, series:[{name,value}]}]
  → mall-web：按 type 套模板渲染看板（交互/PNG/CSV 全前端）
  → 报告模式：AI 网关再调一次 LLM 写 summary 文字
```

- **网关只拿聚合结果（小数据），永不拉原始大数据到内存聚合**（否则网关成瓶颈、阻塞事件循环）
- 聚合在 biz 用 SQL 做，网关 JS 只做轻量后处理
- 单次报表查询 = LLM 1-2 次（1-5s）+ biz 聚合（<1s）→ **一期同步请求完全扛得住**

## 5. 分阶段计划（数据量决定形态）

| 阶段 | 形态 | 触发条件 | 说明 |
|---|---|---|---|
| **一期（本次）** | 同步（复用 `/api/chat`） | 当前数据量小 | biz 直接加 `/api/stats`（SQL 聚合），网关只消费聚合结果——"数据量大了怎么办"在架构上不存在 |
| 二期 | 异步任务 | 单次报表 >5s 或并发上来 | `POST /api/chat` → task_id → 后台执行 → 前端轮询/SSE；LangGraph checkpointer 已有 thread/state 基础，不推倒重来 |
| 三期 | 定时调度 | 运营要"每天 9 点日报" | 是调度器（cron + 推送）场景，不是报表本身 |

**警觉信号**：biz 聚合 >2s → 加索引/物化视图（不是改异步）；报表并发上来 → 异步；要定时/订阅 → 进三期。

## 6. 网关返回结构（AI 不做 UI）

```json
{
  "status": "result",
  "output": "📊 已生成 3 个图表",
  "data": {
    "charts": [
      { "title": "各商品价格对比", "type": "bar", "series": [{ "name": "商品A", "value": 299 }, ...] },
      { "title": "订单状态分布", "type": "pie", "series": [...] },
      { "title": "各商品销量排行", "type": "bar", "series": [...] }
    ],
    "summary": "本周订单整体……（报告模式才有）"
  }
}
```

`data.charts` 数组：一期通常 1~3 个；看板模式多图网格排布。前端按 `type` 套模板（bar/pie/line），每个图带 PNG + CSV 下载。

## 7. 一期范围与决策

- [ ] flyer-biz：`/api/stats` 统计端点（SQL 聚合：按状态分组 / 按月分组 / TopN）
- [ ] flyer-biz：`created_at` 补进 `/api/products` `/api/orders` 返回（趋势图需要时间字段）
- [ ] 网关：`src/skills/report/` 技能包（manifest + LLM 解析 + 消费 stats + 图表数据 + 报告总结）
- [ ] mall-web：echarts 依赖 + 看板组件（charts 渲染 + PNG/CSV 下载）
- [ ] 权限：`data_scopes: [shop]`，商家只看自己店铺（复用 catalog 模式）
- [ ] 缓存：报表数据动态，**不进语义缓存**（缓存会返回过期报表）
- [ ] TopN 限制：默认 Top 10 + 注明"仅显示前10"
- [ ] 描述含糊 → 追问（`needs_input` 机制已有）
- [ ] 图表类型与数据形态校验（饼图要分类+数值、折线要时间轴；缺时间字段 → 明确提示）

## 8. 讨论中明确不做（YAGNI）

- 下钻联动（④分析场景）——一期不做
- 看板"可调节"（拖拽布局/筛选联动）——一期不做，需求明确再加
- LLM 生成 ECharts option——反模式，不做
- 异步任务/定时调度——二期/三期
- 后端出图（canvas 渲染 PNG）——前端 getDataURL 更便宜，除非将来要嵌入文档/邮件
