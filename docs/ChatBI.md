# ChatBI：网关的数据问答能力（report 技能）

> 网关视角文档：定义网关对外契约（业务系统预期提供、前端预期对接）。
> 状态：一期已实现（同步请求）

## 0. 定位

网关新增 **report 技能**：运营人员用自然语言描述数据需求，网关负责
语义解析 → 取数（调业务系统统计接口）→ 返回结构化图表数据 +（报告模式）总结文字。
前端负责渲染，业务系统负责提供聚合数据——网关只管中间这条"语义→数据"链路。

```
运营一句话
  → 网关：LLM 意图识别 + 结构化参数抽取（唯一 AI 环节）
  → 网关：确定性代码校验参数 + 图表类型-数据形态匹配
  → 网关：调业务系统统计接口（业务系统预期提供，SQL 聚合）
  → 网关：返回 charts 数组（数据 + 图表意图，不含 UI）
  → 前端：按契约渲染看板/报告 + 下载（PNG/CSV 由前端实现）
```

## 1. 网关职责与边界（本期）

| 环节 | 承担 | 说明 |
|---|---|---|
| 意图识别 + 参数抽取 | 网关（LLM） | `report_chart` / `report_summary` 双意图，`params.extra` 结构化 |
| 参数校验 + 类型匹配 | 网关（确定性代码） | 折线需时间轴、月份不适合饼图、非法输入回退默认、TopN 前10、无数据提示 |
| 报告总结文字 | 网关（LLM，报告模式） | 第二次 LLM 调用，失败降级（返回 null 不影响图表） |
| 图表渲染 / 下载 | 前端（预期） | option 模板、看板布局、tooltip/缩放、PNG、CSV——**网关不做 UI** |
| 聚合取数 | 业务系统（预期提供） | SQL 聚合，网关只拿聚合结果，不拉原始数据 |

**反模式警示**：网关不生成 ECharts option JSON（UI 是确定性细节，LLM 输出会漂移且浪费 token）；模板在前端。

## 2. 业务系统预期提供（接入契约）

网关的 report 技能需要业务系统提供以下能力，**按此契约实现即可接入**（网关测试环境已有参考实现）：

### 2.1 统计接口

```
GET /api/stats?dataset={products|orders}&group={status|name|month|product}&metric={count|price|stock|amount|quantity}&limit={1-100}
Header: Authorization: Bearer <用户JWT>   （身份 + 数据域过滤）
        X-Biz-Key: <服务间密钥>            （可选，网关配置 BIZ_API_KEY 透传）

200 → { "dataset": "...", "group": "...", "metric": "...",
        "rows": [ {"label": "分类/分组值", "value": 数值} ] }
```

- 业务系统须按当前用户身份过滤数据域（如店铺）——网关不做数据过滤，只透传 JWT
- `group=month` 时 `label` 为 `YYYY-MM`（趋势图时间轴）
- 数据量由业务系统聚合承担；网关只消费 rows

### 2.2 JWT 身份契约（网关鉴权依赖）

业务系统签发的 JWT（RS256）需含以下字段（网关 `verifyJwt` 解析为 UserContext）：

| JWT payload | 语义 | 缺失时的默认行为 |
|---|---|---|
| `sub` | 用户 id | 必填，缺失 = 匿名 |
| `role` | 角色 | 缺省 "user" |
| `skills` | 技能白名单 | **缺省 = 全量放行**（空数组同义） |
| `scopes` | 数据域（如 `["shop:1"]`） | 缺省 = 无数据域隔离 |
| `shop_id` | 店铺归属（数字） | 缺省 = 无店铺维度 |

**最小契约**：只有 `sub/role` 的标准 JWT 也能接入（skills/scopes 缺失按上表默认行为），
但此时网关的权限裁剪与数据域隔离不生效——接入方按需在 JWT 里补充这些字段。

### 2.3 错误格式

业务系统错误统一 `{ "detail": "错误说明" }`（HTTP 4xx/5xx），网关透传为技能失败反馈。

## 3. 前端预期对接（返回契约）

网关 `/api/chat` 对 report 意图的响应：

```json
{
  "status": "result",
  "output": "📊 已生成图表：订单状态分布（数量）",        // 或报告模式的总结文字
  "data": {
    "charts": [
      { "title": "订单状态分布（数量）", "type": "bar",
        "series": [ {"name": "paid", "value": 5}, {"name": "pending", "value": 2} ] }
    ],
    "summary": "（报告模式才有）从订单状态金额分布来看，已支付金额最高…"
  },
  "task": { "id": "...", "steps": [...] }
}
```

- `data.charts`：数组（一期通常 1~3 个，看板模式多图）。`type ∈ bar|pie|line`
- `data.summary`：报告模式的 LLM 总结文字（可选）
- 前端按 `type` 套模板渲染；PNG（截图/汇报）与 CSV（运营二次处理）下载由前端实现
- 网关不承诺 UI：图表配色、布局、交互、下载格式均为前端职责

## 4. 接入其他业务系统的步骤

1. 按 2.2 配置 JWT 公钥（`JWT_PUBLIC_KEY`）与鉴权模式（`AUTH_MODE=jwt`）
2. 按 2.1 实现 `/api/stats`（或实现 report 技能约定的等价接口）
3. 配置 `BIZ_BASE_URL` / `BIZ_API_KEY`，技能内调用即连通
4. 验证：`npm run api` 后问"看看各商品的价格对比"应返回 charts

## 5. 分阶段计划（数据量决定形态）

| 阶段 | 形态 | 触发条件 | 说明 |
|---|---|---|---|
| **一期（当前）** | 同步（复用 `/api/chat`） | 数据量小 | 网关只消费聚合结果，"数据量大了怎么办"在架构上不存在 |
| 二期 | 异步任务 | 单次报表 >5s 或并发上来 | `/api/chat` → task_id → 后台执行 → 前端轮询/SSE；LangGraph checkpointer 已有基础 |
| 三期 | 定时调度 | 运营要"每天日报" | 调度器（cron + 推送）场景 |

**警觉信号**：业务系统聚合 >2s → 加索引/物化视图（不是改异步）；报表并发上来 → 异步；要定时/订阅 → 三期。

## 6. 明确不做（YAGNI）

- 下钻联动、看板"可调节"（拖拽布局/筛选联动）——真实需求明确再加
- 网关生成 ECharts option / 后端出图（canvas）——前端 getDataURL 更便宜，除非将来要嵌入文档/邮件
- 身份适配层（任意 JWT → UserContext 的配置化映射）——等接入第二个真实业务系统时再做
