# PRD：Flyer 商城智能交互网关

> 文档性质：产品需求文档（PRD）
> 版本：v0.3 ｜ 状态：评审中
> 配套文档：[架构与流程图 ARCHITECTURE.md](./ARCHITECTURE.md)

## 1. 背景与目标

### 1.1 背景
商城系统（运营后台 + 前端）与业务系统之间存在**语义鸿沟**：界面产生的自然语言请求（"上架 Nike 鞋 299 元库存 50"）无法直接变成对业务系统的可信执行。本项目定位为**商城智能交互网关**——商城界面与业务系统之间的 Agent 编排层：理解 → 鉴权 → 编排 → 执行 → 反馈。业务系统为外部系统（商城后端），业务能力以**技能（Skill）插件**形式接入，网关本体不绑定任何具体业务。

### 1.2 目标
- P0（当前）：网关基础能力完整（引擎/意图/记忆/持久化/日志）+ 结果契约 + JWT 鉴权 + 任务状态
- P1（规划）：**业务技能**（catalog 商家上架等，对接业务系统 API）
- P2（预留）：平台运营技能（对接业务系统）

### 1.3 非目标（明确不做）
- 不做任何具体业务（业务能力以技能插件接入）
- 不做用户体系/平台业务权限（属于业务方）
- 不做向量检索/历史摘要（预留接口，等痛点出现）

## 2. 用户与场景

### 2.1 目标用户
- 需要搭建对话型 Agent 的开发者（复用 core 减少重复建设）
- 业务技能由外部提供（Skill 插件），核心框架能力由 core 承担

### 2.2 用户故事
| # | 用户故事 | 优先级 |
|---|---|---|
| US1 | 作为开发者，我想注册一个新技能（Skill 子类+manifest），框架自动完成意图路由/记忆/持久化 | P0 |
| US2 | 作为开发者，我想让技能支持多轮对话（澄清追问/承接上文），框架提供 interrupt + 滑动窗口 | P0 |
| US3 | 作为开发者，我想知道每次调用烧了多少 token、哪个技能/会话烧得多，框架自动记录 | P1 |
| US4 | 作为开发者，我想限制某个技能的资源消耗（单次会话/轮数/预算），框架强制生效 | P1 |
| US5 | 作为开发者，我想框架对重复问题做语义缓存，省成本 | P1 |

## 3. 功能需求（core）

### FR-1 对话引擎
- 每轮：意图识别 → 技能路由 → 技能执行 → 记忆写入
- 技能插件机制：`Skill` 子类 + `SkillManifest` 声明（intents）+ 注册表路由
- 验收：任意技能注册后自动接入，core 零改动

### FR-2 多轮对话
- 滑动窗口保留最近 N 轮（`CONTEXT_WINDOW_ROUNDS`，默认 6）
- 意图识别历史感知（"换黑色的"承接上文）
- 技能内 interrupt 澄清（human-in-the-loop 机制）
- 验收：多轮后上下文不丢；澄清最多 N 轮后强制继续

### FR-3 状态持久化
- Checkpointer：memory（原型）/ sqlite（崩溃恢复，落盘）
- 验收：进程重启后同一 thread_id 会话可恢复

### FR-4 可观测性
- JSON 日志 + request_id 贯穿；LLM 调用日志（fn/耗时/token）；降级告警 + 通知器
- 验收：每次调用可追溯（request_id 串联）、降级有告警

### FR-5 Token 治理（P1，资源边界）✅ 核心已实现
- **FR-5.1 用量记录**：按会话（thread_id）+ 技能（manifest.id）拆分 token 用量，持久化可审计
- **FR-5.2 单次控制**：`max_tokens`（输出上限）
- **FR-5.3 会话配额**：会话轮数上限 + token 预算，超限强制拒绝/告警
- **FR-5.4 技能策略**：manifest 声明 `session_mode`（single/multi）/ `max_llm_calls_per_turn`，core 校验
- **FR-5.5 语义缓存**：相同/相似输入直接返回缓存结果（不调 LLM）✅ 已实现（可插拔 embedding）
- 验收：见 5. 成功标准

### FR-6 权限控制（安全边界）✅ 核心已实现
- API 鉴权（服务层）、工具/数据白名单（manifest 扩展）、高危操作人工确认（已有 interrupt 机制）
- **FR-5 与 FR-6 合一为"技能资源与安全边界（SkillBoundary）"**：一个 manifest 声明
  "能花多少（资源）/ 能碰什么（数据工具）/ 什么要批准（闸门）"，core 强制执行（详见 ARCHITECTURE §7）

## 4. 非功能需求

| 项 | 要求 |
|---|---|
| 成本 | token 用量可记录、可限制（FR-5）；dry-run 模式零成本 |
| 可扩展 | 新技能 = 新 Skill 子类；新能力（子图/Store/缓存）= 模块级扩展 |
| 可维护 | core 无业务痕迹；测试覆盖框架能力 |
| 可观测 | JSON 日志 + request_id + 降级告警 + 用量报表（P1） |
| 容错 | LLM 降级回退规则（不中断）；崩溃恢复（sqlite） |
| 合规 | 框架不持有业务数据（数据归业务方，Agent 按需查） |

## 5. 成功标准与评估

| 指标 | 目标 |
|---|---|
| 框架测试 | core 能力用例全绿（当前 24 例，含技能载体） |
| 新技能接入成本 | 注册一个新技能 ≤ 30 行代码（manifest + handle） |
| token 可观测 | 每次调用有用量日志；会话/技能级可汇总（P1） |
| token 可控 | 会话超配额被拦截；语义缓存命中不调 LLM（P1） |
| 崩溃恢复 | sqlite 模式进程重启后会话可恢复 |
