# catalog 技能：商品管理

商家通过对话管理自己店铺的商品（上架/查询/改名/改价/改库存/下架）。
对接业务系统商品 API，JWT 透传验证商家身份与店铺归属。

> 技能包文档范式：每个技能包（`src/skills/<id>/`）应带 README.md，
> 说明 用途 / 意图字段 / 执行流程 / 权限边界 / 缓存策略。本文件即范例。

## 1. 意图与字段

| 意图 | 动作 | LLM 抽取的 params | 说明 |
|---|---|---|---|
| `catalog_add` | 上架 | `name`(商品名) `price` `stock` | 同名商品已存在 → 恢复 on_sale；不存在 → 创建新商品（创建即 on_sale） |
| `catalog_add_batch` | 批量上架 | `extra.table`(粘贴CSV) | 表格驱动：已存在商品 → 更新字段（仅明确"上架"字样才恢复 on_sale）；不存在 → 创建 |
| `catalog_query` | 查询 | `name`(可选) | 指定名称 → 查单个；否则查全部列表 |
| `catalog_update` | 改名/改价/改库存 | `name`(定位旧名) `new_name` `price` `stock` | 部分更新，只传用户指定的字段 |
| `catalog_off` | 下架 | `name` | 状态置 off_sale |

`new_request`（规则兜底）按文本猜测动作：上架 > 下架 > 改价 > 查询。

**字段来源优先级**：LLM `intent.params`（语义抽取）→ `parseProduct` 正则（兜底，无 LLM/漏抽时）。

**表格数据来源优先级**：`state.table_text`（网关打包注入，文件+文字一次提交）→ LLM `extra.table`（对话粘贴 CSV）→ `action_detail` → 全文。

## 2. 执行流程

```
用户输入（可带表格附件：Excel/CSV + 文字描述一次打包）
  → ① 网关区分：表格 → state.table_text（CSV 文本），文字 → user_text
  → ② 意图预筛（trigger_keywords + auto_keywords + embedding 召回；无文字但有表格 → 按"批量处理表格"路由）
  → ③ LLM 意图识别 + 字段抽取（一次调用，返回 intent + params）
  → ④ 代码校验（商品名必填 / 更新值合法性 / 批量列护栏：说改库存但表格只有价格列 → 拒绝）
  → ⑤ 调业务系统 API（X-Biz-Key 服务间鉴权 + 透传用户 JWT）
  → ⑥ verify 回读确认落库（上架/改名/改价/下架后）
  → ⑦ SkillResult 汇报
```

**表格驱动语义**（用户可能"批量上架"也可能"批量调整"，表格内容自己说话）：
- 表格行**不存在** → 创建（on_sale）
- 表格行**已存在** → 只更新表格出现的列（价格/库存），**保留原状态**（不会把下架/草稿商品意外上架）
- 明确说"上架" → 已存在商品恢复 on_sale

## 3. 权限边界

- **JWT 必需**：`user_ctx.token`（业务系统验证身份）+ `user_ctx.shop_id`（店铺归属）
- **数据域**：`data_scopes: [shop]`——商家只能操作自己店铺的商品
- 缺失 token/shop_id → 拒绝："需要业务系统登录态（JWT）"

## 4. 缓存策略

- **仅 `catalog_query` 可缓存**（`cacheable_intents`）——查询是幂等读
- 写操作（上架/改名/改价/下架）**跳过缓存**，防返回过期结果

## 5. 配置

| 配置 | 说明 |
|---|---|
| `auto_keywords: true` | 加载时用 LLM 从意图描述生成 trigger_keywords（与手写合并） |
| `session_mode: single` | 请求级：每次请求独立，无跨轮状态 |
| `max_turns_per_session: 1` | 单会话最多 1 轮 |

## 6. 示例对话

```
上架"Nike 鞋" 299元 库存50        → ✅ 已上架
帮我查一下商品                    → 📦 商品列表
把调试鞋价格改为199              → ✏️ 已更新（部分更新：只改价格）
网页测试鞋名称改为商城测试鞋      → ✏️ 已更新（改名）
撤下调试鞋2                      → 🛑 已下架
```

## 7. 批量 + 表格附件

```
[选表格 商品.xlsx] + "批量上架"         → 📊 批量上架：成功 N 条（不存在创建 on_sale，存在恢复上架+更新）
[选表格 商品.xlsx] + "批量调整价格"     → ✏️ 批量更新：成功 N 条（只改价格列，不动状态/库存）
[选表格 商品.xlsx] + "批量改库存"       → ✏️ 批量更新：只改库存列
[选表格 商品.xlsx]（无文字）            → 📊 表格驱动：已存在更新（保留状态），不存在创建
对话粘贴 CSV（"名称,价格,库存\n鞋A,100,10"） → 同批量处理
"用刚才的表格批量调整价格"（兼容旧流程）  → 读上次上传文件
```

- **一次打包**：web 端选表格 + 输文字一起发送（multipart），网关区分表格与文字描述
- **id 列支持**：表格带 id 列 → 按 id 精确定位（名称可能已变）；名称列与系统不一致 → 以表格名称为准（改名）
- **描述与表格的关联判定**（两者可能无关）：
  - 描述**引用**表格（"根据表格调整X""用表格批量上架"）→ 合并处理：表格数据 + 描述意图
  - 描述**未引用**表格（"把调试鞋价格改为199"+ 表格附件）→ **分别处理**：描述独立执行 + 表格独立处理，结果合并汇报
  - 无文字只有表格 → 表格驱动（存在更新含改名，不存在创建）
- **描述与表格一致性**（两者可能不重合，LLM 抽条件、代码确定性校验）：
  - 条件过滤：`filters`（价格/库存上下限、排除名单、状态）→ 不满足的行**跳过并汇报**（跳过≠失败，不影响整体 success）
  - 数量校验：说"这N个商品"但表格行数不符 → 拒绝并提示
  - 全部被过滤 → 明确提示"没有符合条件的商品行"
- **列护栏**：说"批量改库存"但表格只有价格列（或反之）→ 拒绝并提示，绝不改错列
- **意图护栏**：LLM 误判批量上架/调整时，按文本中的改价信号确定性改走 update
